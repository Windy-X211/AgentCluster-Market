# 任务进度邮件通知（Progress Email Notify）

让智能体在**执行长任务**（批量处理、数据抓取、长文生成、多步骤流水线等）的过程中，**定时或分阶段**把进度快照邮件发到用户邮箱，用户无需盯着对话窗口也能实时掌握任务进展。

> **核心机制**：邮箱配置（SMTP 服务器/端口/发件邮箱/授权码/收件邮箱）在**首次使用时**通过弹出 GUI 窗口让用户填写，测试成功后**保存到本地**；后续运行直接复用，不再弹窗；只有用户明确要求"重新配置"才再次弹出。

---

## 何时使用

### ✅ 应该加载
- 用户启动了长任务，并**明确要求**发进度邮件：*"进度发我邮箱" / "每 15 分钟给我发封进度邮件" / "处理完 1000 个文件后发邮件告诉我"*
- 用户要求**定时汇报**：*"每小时汇报一次" / "每 5 分钟汇报"*
- 用户要求**分阶段汇报**：*"每个阶段完成时发邮件" / "每完成 50 条就发一次"*
- 用户要求**任务完成通知**：*"跑完发邮件提醒我" / "完成时通知我"*
- 用户要求**重新配置邮箱**：*"重新配置邮箱" / "改邮箱" / "换个收件邮箱" / "邮箱换一下"*

### ❌ 不要加载
- 用户只是随口说"记得告诉我"，没有明确要求**发到邮箱** → 直接在对话里汇报即可。
- 一次性短任务（几秒内完成）→ 没必要发邮件，直接对话汇报。
- 纯本地、用户就在电脑前的轻任务 → 提醒即可，不发邮件浪费配额。

## 邮箱配置（一次性 GUI 配置，之后自动复用）

### 第 0 步：检查配置是否存在（每次激活必做）

```powershell
Test-Path "$env:LOCALAPPDATA\AgentCluster\userdata\email_config.json"
```

- **存在** → 进入[「已有配置」](#已有配置直接复用不弹窗)流程，**跳过弹窗**。
- **不存在** → 走下方[「首次配置」](#首次配置弹窗采集)流程，**必须让用户先完成配置**，配置成功前不得发送进度邮件。

### 首次配置（弹窗采集）

```
python "C:\Users\yangq\AppData\Local\AgentCluster\skills\progress-email-notify\scripts\email_config_gui.py"
```

弹窗会打开一个 tkinter 图形窗口，包含：

| 字段 | 说明 |
|------|------|
| 常用邮箱预设 | 下拉选择 QQ / 163 / 126 / Gmail / Outlook，自动填充服务器与端口 |
| SMTP 服务器 | 如 `smtp.qq.com` |
| 端口 & SSL | 465(SSL) / 587(STARTTLS)，自动按预设填入 |
| 发件邮箱 | 用户自己的邮箱地址（登录账号） |
| 授权码 / 密码 | **不是登录密码**，是邮箱的 SMTP 授权码（提示用户去邮箱设置里开启 SMTP 并生成授权码） |
| 发件昵称（可选） | 收件方看到的发件人显示名 |
| 收件邮箱 | 进度邮件发往哪个邮箱（可与发件邮箱相同） |

**流程**：填写 → 点【测试发送】→ 收到"测试邮件发送成功" → 点【保存并退出】。保存后生成 `$env:LOCALAPPDATA\AgentCluster\userdata\email_config.json`（存用户级目录，**不在技能文件夹内**，分享技能时不会泄露）。

> **智能体职责**：窗口弹出后，**等待**用户操作完成。若用户问"其中一项是什么"，对照上方表格解释；若用户说"测试失败了"，读取弹窗错误信息，给出对应排查建议（见[故障排查](#故障排查)）。

### 已有配置（直接复用，不弹窗）

配置文件已存在时：
1. 直接读取 `$env:LOCALAPPDATA\AgentCluster\userdata\email_config.json` 获得 `host / port / ssl / user / password / to / nick`。
2. **不回显 password**——读取后只向用户确认"使用已保存的邮箱配置（发件：x***@***.com）"，不要把授权码打出来。
3. 直接进入发送流程。

### 重新配置

用户说"重新配置邮箱 / 换个邮箱 / 改设置"时：
1. 运行 `email_config_gui.py` 重新弹窗，用户改完后保存，**覆盖** `$env:LOCALAPPDATA\AgentCluster\userdata\email_config.json` 原配置。
2. 若用户只改某一项（如收件邮箱），可以只运行 `send_progress_email.py` 时用命令行参数覆盖，但建议统一走 GUI 覆盖，避免配置与文件不一致。

## 工作流程

### A. 分阶段汇报（每个阶段完成时发一封）

适用于多阶段长任务（每个阶段可明确划分进度）：

1. **接受任务时**：先向用户确认**阶段划分**（例如：数据采集 → 清洗 → 分析 → 生成报告），以及**每阶段完成是否都发邮件**。
2. **每完成一个阶段**：
   - 生成该阶段的进度快照（阶段名、已用时间、该阶段完成说明、下一步计划）；
   - 调用发送脚本发邮件；
   - 在对话里向用户确认"已发送"。
3. **全部完成**：发一封**任务完成邮件**（含最终总结）。

发送示例（由智能体代发）：

```powershell
python "C:\Users\yangq\AppData\Local\AgentCluster\skills\progress-email-notify\scripts\send_progress_email.py" `
  --subject "【进度】数据采集阶段已完成 (2/5)" `
  --body-file "$env:TEMP\progress_snapshot.txt"
```

### B. 定时汇报（按固定间隔发）

适用于长任务需要周期汇报的场景：

1. **接受任务时**：和用户确认**间隔**（如每 10 分钟 / 每 30 分钟 / 每小时，取 ≥ 1 分钟），以及**汇报内容**（进度百分比 + 当前步骤 + 异常）。
2. **执行期间**：每个间隔到达时，生成当前进度快照并发送；对话内只做简短登记，不重复汇报正文。
3. **关闭定时**：任务结束或用户喊停时不再发送，并明确告知用户"已停止定时汇报"。

> 定时实现由智能体在任务执行循环里按间隔驱动，不必额外起后台进程；若智能体运行环境支持后台任务，也可用后台线程 + 配置文件里的间隔，但**必须**在收尾时确保线程停止。

### C. 任务完成通知（只发一封）

适用于"完成后提醒即可"的场景：

1. 任务开始时不发（或只发一封"任务已开始"）；
2. 任务完成后发一封总结邮件：总耗时、完成项、产出位置、失败项与原因。

## 邮件内容规范

邮件正文统一走 `assets/email-template.md` 提供的 3 类模板：**分阶段汇报 / 定时汇报 / 任务完成**。要点：

- 主题统一加前缀：
  - 分阶段：`【进度】<阶段名> <n/m>`
  - 定时：`【定时汇报】<任务名> <HH:MM>（进度 x%）`
  - 完成：`【完成】<任务名> 已完成`
- 正文：Markdown 的纯文本版（**发送前把 `**` 等 Markdown 符号转为纯文本**，或保留为易读的带空行的纯文本），包含：任务名、当前进度、已完成/待办、异常提示、下一动作。
- 语言跟随用户语言；默认简体中文。

## SMTP 常见配置速查

| 邮箱 | SMTP 服务器 | 端口/加密 | 授权码说明 |
|------|------------|-----------|-----------|
| QQ 邮箱 | `smtp.qq.com` | 465 / SSL | 设置→账户→开启 SMTP 生成授权码 |
| 163 邮箱 | `smtp.163.com` | 465 / SSL | 设置→POP3/SMTP→开启→客户端授权码 |
| 126 邮箱 | `smtp.126.com` | 465 / SSL | 同上 |
| Gmail | `smtp.gmail.com` | 587 / STARTTLS | 需开启"应用专用密码"或两因素 |
| Outlook | `smtp.office365.com` | 587 / STARTTLS | 账号密码即可（组织账号需管理员） |

## 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 测试发送失败 `Authentication failed` | 授权码错误 / 未开启 SMTP | 让用户去邮箱设置里重新生成授权码 |
| `Connection refused / timeout` | 端口或服务器错 / 网络 | 核对预设表；公司网络常封 25 端口，改用 465/587 |
| `SSL: WRONG_VERSION_NUMBER` | 端口用了 465 却走 STARTTLS | 465 用 SSL、587 用 STARTTLS，别混 |
| `SMTPServerDisconnected: Connection unexpectedly closed` | 端口与加密方式不匹配（465 配了 STARTTLS / 587 配了 SSL），或服务器风控 | 已内置自动重试：按端口依次尝试 ssl→starttls→plain（见 `scripts/smtp_utils.py`）；仍失败则核对端口与加密是否对应，或稍后再试 |
| 报 `smtplib` 模块缺失 | Python 环境异常 | 系统自带标准库，重装 Python 或换解释器 |
| 保存后仍弹窗 | 配置文件路径不对 | 确认文件在 `$env:LOCALAPPDATA\AgentCluster\userdata\email_config.json`，用 `Test-Path` 检查 |

## 安全与边界（P0）

- **不硬编码**：技能里没有任何真实邮箱/授权码（全部占位符），配置只在用户本机 `$env:LOCALAPPDATA\AgentCluster\userdata\email_config.json`（**技能文件夹之外**，防止把技能目录整个分享时随目录泄露凭据）。
- **不回显凭据**：任何时候不打印 password/授权码；向用户确认配置时只显示脱敏对象（`x***@***.com`）。
- **不泄露任务内容**：邮件正文默认只含进度快照；涉及机密文件内容/内部数据时，先征得用户同意再写入正文。
- **不发骚扰邮件**：定时汇报间隔默认 ≥ 5 分钟；用户喊停立即停止；任务结束自动结束定时。
- **失败如实反馈**：发送失败把 `error` 转述给用户，绝不假装已发送；最多自动重试 1 次。
- **配额保护**：若连续 3 次发送都报限流/失败，停下来让用户决定（换邮箱/降低频率），不无限重试。

## 启用方式

1. 技能目录已生成：`AppData\skills\progress-email-notify\`（含 SKILL.md、scripts/、assets/）。
2. 在智能体配置的 `skills` 列表中加入 `progress-email-notify`。
3. 若系统未识别，调用 `POST /api/commands/reload` 热加载或重启后端。
4. 首次使用时智能体自动弹窗让用户配置邮箱；之后直接复用。
